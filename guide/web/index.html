Hide chat, clean Gist, or remove old data?
Hide on this device
Chat → Manage history → Keep the latest 10 or Hide read messages. Restore hidden messages brings back only messages still available from the relay.
Clean the current Gist
Ask Muse to extend the one existing writer with cleanup after successful processing. The reference watcher keeps the latest 50 rows it created, preserves other records, and removes confirmed requests with their own input attachments.
Past versions
Hiding in Muse Relay does not delete relay data. Removing a file from the current Gist does not erase its revision history. The app does not restore messages already pruned by your relay.

If messages or Spaces seem to disappear as a Gist grows, ask the maintainer to check whether GitHub truncated the file list. That is separate from a large individual file needing a raw-content fetch. The reference watcher stops on a truncated file list.

First checks

1 · Save your relay choice

Settings → Connection → choose a relay → Check connection → Save settings. In the wizard, use Save and open.

After saving, check the Gist or Muse Gadget label at the top of the app. The settings form may still contain unsaved changes.

2 · Send text → find the matching reply
Gist
Send a short message in Chat. Your watcher and Muse handler must return a reply to that message.
Muse Gadget SDK · ATOM / Linux
Send a short message in Chat. The device or adapter must pass it to the paired Muse conversation and return its reply.

Success: your input and its Muse reply appear in the app, then on G2. Connected only confirms relay access; Device online only confirms recent device communication.

3 · Send voice → check words and reply

Voice & images → Transcription service → Transcribe via relay. Select the microphone, save, record a short phrase, then send. Soniox is not required.

Gist
Your Muse-side handler transcribes the WAV and returns the words and reply to the watcher.
Muse Gadget SDK · ATOM / Linux
The adapter sends WAV to Muse. The app can show your words only when a matching user transcript is returned.

Check two results separately: your recognized words, and the Muse reply. A reply alone does not confirm that the transcript was exported.

Reply arrived, but no transcript →
4 · Mobile data → repeat one message

Turn off Wi-Fi on the phone, keep G2 connected, and send a new short message. Check its matching reply. Leave the home device powered and connected to Wi-Fi.

Gist
Your watcher and Muse handler must remain running while you are away.
Muse Gadget SDK · ATOM / Linux
The phone uses your external HTTPS relay, not the home device’s LAN IP. The home device connects outward to that relay.
If the connection check stops
Cannot read the Gist
Check the Gist ID, token permissions, and g2muse-relay.json.
HTTPS relay returns 403
In Connection settings for your server, copy This app’s origin to the relay settings. The reference setup's Allow local Even app connections option handles Even's variable local port.
Connected, but no reply
The connection check only reads data. Check the Gist handler or the Gadget's Muse pairing and processing state.
Device is online
This shows recent device communication, not a successful Muse reply.

Live words while speaking (optional)

Choose Soniox (direct from app), then Enter API key or Temporary key server. Select Check Soniox connection, save, and try a short recording.

Look for words while speaking, final text after Send, and then a matching Muse reply. The Soniox check uses silence; it does not test your microphone or Muse.

Reply arrived, but no transcript

First check the saved relay and transcription service. Keep the request ID and result type for diagnosis; do not post recordings, keys, or private text.

Gist
Ask Muse to return transcript from the handler. The watcher must update the original You message, not append the words as a Muse reply.
Muse Gadget SDK · ATOM / Linux
Ask the relay maintainer to check the matching SDK message.user and its display_text, text, or content. If it is missing, a reply may still arrive with only a voice label for your input.
For consistent live input text
Use Soniox. It sends the final recognized text through either relay, rather than waiting for a Muse-side transcript.
